## What's NOT done (deferred from M1)

### AI subsystem still intact
The plan's primary goal was stripping the entire AI subsystem. That was much bigger than the design assumed — Terax has deep AI integration including:

- `src/modules/ai/` (whole directory: tools/, agents/, components/, hooks/, lib/, store/, config.ts, ~25 files)
- `src/components/ai-elements/` (9 files of AI-rendering components)
- `src/modules/statusbar/AiTools.tsx`
- `src/settings/sections/ModelsSection.tsx` (AI provider config)
- `src/settings/sections/AgentsSection.tsx` (agent persona config)
- `src/settings/components/ProviderIcon.tsx`
- `src-tauri/src/modules/secrets.rs` (keyring for API keys)
- 8 `@ai-sdk/*` packages in `package.json`
- `App.tsx` has ~10 imports from `@/modules/ai/*` and mounts AI surfaces
- Voice input via `src/modules/ai/hooks/useWhisperRecording.ts`

**Current state:** the AI features are still visible in the app when launched, but everything is Oasis-branded. Aggressive deletion was deferred to avoid leaving the codebase in a broken state at 3am.

### Capybara icons
The video mentioned "capybara file icons" but the actual upstream uses a **Catppuccin** icon theme (Material Icon Theme resolver, per the README). There is a `terax-icon.png` app icon at the root that should be replaced for a v1 release. No capybara found anywhere — that was a video-watch interpretation error.

### Internal symbol renames
TypeScript types like `TeraxOpenInput`, Tauri event names like `"terax:settings-tab"` and `"terax:ai-attach-file"`, and Rust shell-init constants still use the `Terax`/`terax` identifier. They don't break the build (Cargo lib name `oasis_lib` is what matters for linkage), but they're inconsistent and should be cleaned up.

### AiDiff tab kinds in useTabs / tabs

`AiDiffStatus`, `AiDiffTab` types; `openAiDiffTab`, `setAiDiffStatus` methods exported from `@/modules/tabs`. `TabBar.tsx` has an `ai-diff` case in `TabIcon` and `labelFor`.

### settings/store.ts coupling

Imports `DEFAULT_AUTOCOMPLETE_MODEL`, `DEFAULT_MODEL_ID`, `LMSTUDIO_DEFAULT_BASE_URL`, `AutocompleteProviderId`, `ModelId` from `@/modules/ai/config`. These are used in the `Preferences` type and defaults for autocomplete settings. The preferences type itself has AI fields (`defaultModelId`, `autocompleteProvider`, etc.) but these are stored preferences that non-AI parts of the app read. Strategy: inline the constants we need and replace the AI-module types with plain `string`.
